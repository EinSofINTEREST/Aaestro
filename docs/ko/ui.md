# Web UI

한국어 | **[English](../en/ui.md)**

Control Plane 은 `/ui` 에서 운영자 화면을 서빙한다. 에이전트 시스템을 조립하고 띄우고
구동하는 일을 `curl` 나열이 아니라 브라우저에서 하기 위한 것이다. 빌드 단계도, 별도
프로세스도 없다 — 화면은 패키지에 함께 실리고 [Control Plane API](api.md) 를 `fetch` 로만
부른다. 파일시스템이나 Docker 에 직접 닿지 않으므로, UI 가 할 수 있는 일은 전부 API 로도
할 수 있다.

```bash
python -m aaestro.orchestrator      # API 와 UI 를 함께 서빙한다
```

`http://127.0.0.1:8700/` 을 열면 `/ui/` 로 리다이렉트된다.

## 연결

화면은 토큰 없이 열린다. 토큰 없이 무엇을 읽을 수 있는지는 control plane 에 달렸다 —
`orchestrator.control_token` 이 설정돼 있으면 **토큰** 칸에 넣고 **연결** 을 누르고, 토큰이
설정되지 않았다면 (loopback 바인드에서만 허용된다) API 가 열려 있어 화면이 바로 데이터를
불러온다. 옆의 표시가 결과를 알려준다:

| 표시 | 의미 |
|---|---|
| 미연결 | 아직 토큰을 넣지 않았다 |
| 연결됨 | 토큰이 통했다 — 카탈로그·배포·run 을 불러왔다 |
| 토큰 거부 | 토큰이 없거나 틀렸다 (`401`) |
| 연결 실패 | control plane 에 닿지 못했다 |

토큰은 `sessionStorage` 에 둔다 — 새로고침에는 남고 탭을 닫으면 사라진다. 디스크에 쓰지
않는다.

## 여섯 개의 탭

### 카탈로그 — 무엇으로 조립할 수 있는가

에이전트·그래프·그룹·모듈 네 목록. 항목을 고르면 파싱된 선언 전문이 보인다.

파싱에 실패한 선언은 사라지는 대신 아래쪽 목록에 파일 경로와 에러 코드로 나온다. 이 구분이
중요하다 — 빈 에이전트 목록은 "선언된 것이 없다"이고, problem 항목은 "이 파일을 고쳐야
한다"이다.

### 그래프 편집기 — 배선

캔버스가 아니라 폼이다. 메타 블록은 이름·버전·설명·모드·목표·state(필드 JSON —
`{"query": {"type": "string", "required": true}}` — 또는 deprecated 인 schema 참조)를 담고,
그 아래 표 세 개가 실제 배선을 담는다:

- **노드** — id 와 그것이 물릴 에이전트. 에이전트는 카탈로그에서 온 드롭다운이라, 존재하지
  않는 것을 가리킬 수 없다.
- **엣지** — `from`, `to`, 선택적 조건(`state.needs_research` 같은 식 —
  [modules.md](modules.md) 참조), 순환에 필요한 `max_iterations`.
- **connections** — A2A allowlist. `caller`/`callee` 선언이 있어야 실행 중 한 에이전트가
  다른 에이전트에게 위임할 수 있다. 없으면 호출이 거부된다.

모드를 `service` 로 바꾸면 idle 정책 필드가 나타난다 — backoff 없는 상주 그래프는 모델
호출을 busy loop 으로 낭비하므로, 그 모드에서는 필수 입력이다.

**검증** 은 초안을 `POST /v1/validate` 로 보내 finding 을 검사 이름·코드와 함께 나열한다.
**저장** 은 먼저 검증하고 하나라도 실패하면 쓰지 않는다 — UI 를 통해서는 유효하지 않은
그래프가 디스크에 닿지 않는다.

**카탈로그에서 불러오기** 는 기존 그래프를 불러오면서 patch 버전을 올려 둔다. 같은 버전으로
바뀐 내용을 저장하는 것은 거절되기 때문이다 — 버전이 곧 배포의 재현 가능성이다.

### 에이전트 편집기 — 매니페스트

같은 방식의 매니페스트 폼: 메타와 그룹, 모델, 모듈 참조, 런타임 블록(이미지, entrypoint,
`env_allowlist`, A2A 노출 여부).

모듈 참조는 카탈로그의 게시된 버전으로 만든 드롭다운이다. 자유 입력도 `latest` 도 없다 —
모든 참조는 실재하는 버전에 고정된다.

#### 빌드 재료 — 커스텀 에이전트

매니페스트 폼 아래가 재료 편집기다. 폼에 적힌 이름의 **저장된** 에이전트, 그 현재 버전을
다루므로 에이전트를 먼저 저장한다.

1. **재료 불러오기** 는 스토어가 그 버전에 갖고 있는 재료를 불러오고 빌드 상태를 보여 준다.
2. **+ 파일** 은 경로와 내용 한 행을 더한다. 경로는 `Dockerfile` 이거나 `src/` 아래여야
   한다. 규칙을 어긴 경로는 **입력하는 동안** 빨갛게 나열되고, 하나라도 있으면
   **재료 저장** 이 아무것도 보내지 않는다.
3. **재료 저장** 이 행들을 저장한다. `Dockerfile` 을 빼면 스켈레톤으로 굽고, 스켈레톤은
   `src/` 를 import 경로에 올린다 — `src/agent.py` 의 클래스를 돌리려면 **entrypoint** 에
   `agent:MyAgent` 를 적는다. **image** 는 비워 둔다: 커스텀 에이전트는
   `aaestro/agent-<name>:<version>` 으로 돌고, 다른 이미지를 적으면 배포가 거절한다.
4. **빌드** 는 빌드를 제출하고 끝날 때까지 따라간다:

| 상태 줄 | 의미 |
|---|---|
| 재료 없음 | 재료가 없다 — declarative 에이전트, 구울 것이 없다 |
| 아직 굽지 않음 | 재료는 저장했지만 구운 적이 없다 |
| building | 굽는 중 |
| built | 이미지가 있고 배포가 쓸 수 있다 |
| failed | 줄 아래에 Docker 출력의 꼬리가 펼쳐진다 — 원인은 그 끝에 있다 |

한 버전의 재료는 저장한 뒤에 바꿀 수 없다. 실패한 빌드를 고치려면 버전을 올려 에이전트를
저장하고, 새 재료를 저장해 굽는다. 이미 그래프가 그 에이전트를 참조하고 있으면 둘 중 하나만
저장해도 참조가 깨지므로, `PUT /v1/declarations` 로 함께 바꾼다.

### 배포 — 컨테이너

그래프를 고르고 **배포** 를 누르면 에이전트별 컨테이너 id·포트와 배포 상태(`starting` →
`ready`, 실패면 사유와 함께 `failed`)가 행으로 나타난다. **해체** 는 drain 후 컨테이너를
정지시키고, 기록은 `stopped` 로 남는다.

그래프를 고르면 그 에이전트들의 빌드도 확인한다. 재료가 있는데 그 버전의 `built` 이미지가
없거나 (또는 `built` 기록의 태그가 배포가 띄울 태그와 다른) 에이전트가 있으면 폼 아래에 나열하고, 구울 때까지 **배포** 를 잠근다. control plane 도
같은 규칙을 스스로 강제한다 (`409`, `RT_012`) — 탭은 누르기 전에 보여 줄 뿐이다.

여기서 자주 보게 되는 두 거절은 모두 살아 있는 배포를 지키는 동작이다:

- 이미 다른 배포로 도는 에이전트를 쓰는 그래프의 배포는 거절된다 (`409`). 그쪽을 먼저
  해체한다.
- 살아 있는 배포가 쓰는 에이전트·그래프의 저장은 편집기에서 거절된다. 배포된 시스템을
  바꾸려면 새 버전을 배포하고 옛것을 해체한다.

### Run — 구동

준비된 배포를 고르고 초기 state 를 JSON 으로 넣어 제출한다. 제출은 `run_id` 와 함께 즉시
돌아오고, 표가 완주까지 폴링한 뒤 최종 state 를 보여준다.

행에는 그 상태에 해당하는 조작만 붙는다 — 전체 기록을 보는 **보기**, 실행 중 service run 의
**drain** (현재 iteration 후 정지), 그리고 `halted` 또는 `failed` 인 run 의 **재개**.
재개의 의미는 모드마다 다르다 — service run 은 마지막 iteration 부터, mission run 은 마지막
checkpoint 부터다. 정확한 계약은 [API 레퍼런스](api.md#post-v1runsrun_idresume) 참조.

### 권한 — 누가 무엇을 할 수 있는가

control plane 이 권한 레지스트리를 켰을 때만(`orchestrator.access_store`) 열린다 — 아니면 탭이 꺼져
있다고 알린다. 에이전트를 고르면 네 가지를 본다:

| 구역 | 보여 주는 것 |
|---|---|
| 선언 권한 | 매니페스트·소속 그룹·`global`·지금 배포된 그래프가 주는 것 — memory space 와 그 모드, A2A 피호출자, 이그레스 목적지, 원격 MCP 도구 |
| 부여·회수 기록 | 회수와 부여 전부 — 결정 주체(`operator` 또는 권한 에이전트), 요청자, 사유, 만료, 그리고 `active`·`expired`·`lifted` |
| 확장 상한 | 권한 에이전트가 이 에이전트에게 줄 수 있는 최대 범위, 소속 그룹과 `global` 에서 |
| 최근 거부 | 레지스트리가 이 에이전트에게 내린 최근 거부 |

**회수.** 사유를 적고(기록에 남는다) 선언 권한 줄의 버튼을 누른다. 쓰기가 되는 memory space 에는 둘이
있다 — **쓰기 회수** 는 쓰기만 막고 읽기를 남기며, **전체 회수** 는 둘 다 막는다. 그 밖의 권한에는
**회수** 하나다. 회수는 그 에이전트의 **다음 요청**부터 적용된다 — 컨테이너를 재시작하거나 재배포하지
않는다.

**되돌리기.** 살아 있는 기록에는 버튼이 붙는다 — **되돌리기** 는 회수를 되돌리고, **끝내기** 는 부여를
일찍 끝낸다. 기록은 `lifted` 로 남는다.

넓히기는 여기 없다. 부여는 상한 안에서 권한 에이전트가 하고, 상한은 그룹 선언에서 바꾼다. 긴급 상황은
[권한 통제 runbook](runbooks/access-control.md) 을 본다.

## 전체 흐름

메인 목표가 요구하는 것은 결국 이 탭들을 순서대로 쓰는 일이다:

1. **카탈로그** — 어떤 에이전트와 모듈이 있는지 본다.
2. **에이전트 편집기** — 에이전트를 추가하거나 고쳐 저장한다. 커스텀 에이전트는 빌드 재료를
   저장하고 **빌드** 를 눌러 `built` 가 될 때까지 기다린다.
3. **그래프 편집기** — 노드를 놓고, 엣지를 잇고, A2A 연결을 선언한다. 깨끗해질 때까지
   검증하고 저장한다.
4. **배포** — 그래프를 배포하고 에이전트가 healthy 로 바뀌는 것을 본다.
5. **Run** — 입력을 제출하고 결과를 본다.
6. **권한** — 도는 동안 에이전트가 닿는 범위를 좁힌다. 회수하면 재시작 없이 다음 요청부터 거부된다.

파괴는 같은 길의 역순이다: 배포를 해체한 뒤 그래프나 에이전트를 삭제한다 (참조가 남아
있으면 삭제는 거절된다).

## UI 가 의도적으로 하지 않는 것

- **드래그 앤 드롭 캔버스 없음.** 배선은 표다. 캔버스에는 프론트엔드 툴체인이 필요하고,
  그것은 아직 내려지지 않은 의존성 결정이다 (이슈 #252).
- **실행 중 시스템의 in-place 편집 없음.** 모든 변경은 저장 → 배포 → 해체를 지나므로,
  돌고 있는 것은 언제나 디스크의 선언과 일치한다.
- **secrets 없음.** UI 는 에이전트 토큰이나 secret 값을 보여주지 않는다. secrets 는
  control plane 의 환경에서 `env_allowlist` 를 통해 컨테이너로 간다.

## 문제 해결

| 증상 | 원인 |
|---|---|
| 토큰을 넣었는데 토큰 거부 | `orchestrator.control_token` 과 다르다 |
| 배포 탭이 비어 있고 배포가 실패 | `orchestrator.deployment_store` 미설정 — 배포 표면이 닫혀 있다 |
| 버전 관련 메시지로 저장 거절 | 내용은 바뀌었는데 버전은 그대로다 — 올린다 |
| "currently deployed" 로 저장 거절 | 배포를 먼저 해체한다 |
| run 이 즉시 `GRAPH_002` 로 끝남 | 에이전트가 노드를 실행하지 못했다 — 해당 컨테이너 로그를 본다 |
| 빌드 경고와 함께 배포가 잠김 | 그래프의 에이전트에 재료는 있는데 `built` 이미지가 없다 — 에이전트 편집기에서 굽는다 |
| **빌드** 가 "agent has no build materials" 로 답함 | 재료를 먼저 저장한다 — declarative 에이전트는 굽지 않는다 |
| 버전 메시지로 재료 저장 거절 | 그 버전의 재료는 불변이다 — 에이전트 버전을 올린다 |
| 빌드 상태가 없고 **빌드** 가 `404` | `orchestrator.material_store` 또는 `orchestrator.build_store` 미설정 |
| 권한 탭이 레지스트리가 꺼져 있다고 함 | `orchestrator.access_store` 미설정 |
| 회수가 `active` 인데 에이전트가 계속 함 | 강제 지점이 레지스트리에 닿지 못해 캐시된 허용을 쓰고 있다 — [runbook](runbooks/access-control.md#레지스트리에-닿지-않을-때) 참조 |

각 화면 뒤의 정확한 상태 코드와 페이로드는 [Control Plane API](api.md) 를 참조한다.
